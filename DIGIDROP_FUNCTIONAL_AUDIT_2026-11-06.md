# DigiDrop — функциональный аудит перед рабочим тестом
Дата: 2026-11-06

## Подтверждено по текущему исходному коду main

- Android-приложение собирается в GitHub Actions (debug APK).
- Камера подключена через CameraX, распознавание — Google ML Kit.
- Импорт реализован только для текстовых CSV/TSV. XLSX и PDF не разбираются.
- Импорт ожидает плоские строки с полями штрихкод, точка/адрес и количество мест.
- Демо-маршрут при старте пустой.
- Можно открыть внешнюю карту/навигацию по адресу или координатам.
- Статусы и часть счётчиков сохраняются в SharedPreferences.
- Есть экспорт отчёта CSV.

## Критические несоответствия рабочему сценарию

### 1. Нельзя считать одинаковые упаковки по одному товарному штрихкоду
Сейчас обработчик сканирования ищет первую строку, где `RouteItem.barcode == scannedCode`, а затем хранит отсканированные значения в `StringSet`. Повтор того же значения объявляется дубликатом. Это означает, что 5, 10 или 30 одинаковых коробок с одинаковым EAN/GTIN будут ошибочно считаться одной упаковкой. Нельзя использовать товарный штрихкод как уникальный идентификатор физической коробки.

Правильное поведение: трактовать код товара как признак номенклатуры; искать все строки/точки, где ожидается этот товар; показывать список возможных точек и количество по каждой. Если код содержит уникальный SSCC/серийный идентификатор, его можно учитывать отдельно как уникальную упаковку.

### 2. Модель данных слишком плоская
Сейчас одна строка представлена как одна `RouteItem`. Нет отдельных сущностей рейса, точки, накладной, товарной позиции и уникальной упаковки. Поэтому корректное объединение нескольких накладных одной точки и суммирование одинаковой номенклатуры не гарантированы.

### 3. Прогресс привязан к штрихкоду строки
Ключи SharedPreferences вида `delivered_<barcode>` и `scanned_<barcode>` конфликтуют, когда штрихкод товара повторяется в разных накладных или точках. Нужны стабильные идентификаторы накладной/позиции/точки и явная область действия счётчиков.

### 4. Импорт не соответствует неизвестному пока файлу логистики
CSV/TSV поддержан частично. XLSX, несколько листов, сложные заголовки, отдельные таблицы соответствия кодов и накладных не реализованы. До получения обезличенного реального файла нельзя достоверно определить схему импорта.

### 5. Геокодирование не является дорожной оптимизацией
При наличии координат применяется простая сортировка по прямому расстоянию. Без координат исходный порядок сохраняется. Это не расчёт дорожного маршрута.

## Безопасный объём ближайшей реализации

1. Разделить товарный код и уникальный код упаковки (если он существует).
2. При совпадении товарного кода показывать все подходящие точки, товар и ожидаемое количество, не выбирать первую точку молча.
3. Объединять позиции по точке и накладной, суммировать одинаковую номенклатуру без потери документов.
4. Не увеличивать счётчик физических коробок от повторного чтения общего товарного EAN.
5. Хранить подтверждения сканирования только для действительно уникальных кодов упаковок.
6. Сохранять импортированный рейс и прогресс с устойчивыми ID, а не ключами на основе товарного штрихкода.
7. Добавить XLSX после получения примера реальной выгрузки и тестировать импорт на обезличенном файле.
8. Добавить тесты на одинаковый товар в нескольких точках, несколько накладных одной точки, дубликат уникального SSCC, неизвестный код и восстановление после перезапуска.

## Что нельзя честно заявить сейчас

- Что приложение определяет конкретный магазин по общему штрихкоду товара.
- Что оно умеет распознавать и импортировать Excel/PDF.
- Что оно уже сверяет физическое количество одинаковых коробок.
- Что оно проверено на рабочих этикетках и реальном Android-устройстве.
- Что маршрут оптимизируется по дорогам.

## Итог
Текущая успешная CI-сборка подтверждает компиляцию APK, но не готовность к рабочей логистике. Самый опасный дефект — текущая логика считает одинаковый товарный штрихкод дубликатом, хотя в реальности таких упаковок может быть много. До получения реального формата накладной правильнее показывать неоднозначные совпадения и не выдавать догадку о точке за достоверный результат.
