# DigiDrop — release backlog и точка продолжения

Обновлено: 2026-11-08
Ветка: `main`
Назначение: единый список того, что ещё нужно довести до рабочего релиза. Этот файл не означает, что перечисленные функции уже реализованы или проверены.

## Жёсткие решения проекта

- Только ветка `main`. Новые ветки не создавать.
- Сборка APK — только GitHub Actions; локальную сборку не использовать.
- Offline-first: локальная Room DB, без Firebase, облачной синхронизации и сторонней авторизации.
- Офлайн-карту региона полностью исключили. Не скачивать тайлы/PMTiles, не собирать карту и не возвращать экран офлайн-карты.
- Для навигации использовать Яндекс Навигатор. Не Google Maps.
- Интерфейс: industrial / graphite, крупная плотность, большие читаемые элементы, приглушённая светлая тема и графитовая тёмная тема с зелёными акцентами.
- Главный экран: одна заметная кнопка «Загрузить накладную» до импорта; после загрузки показывать рабочий список точек. В списках — компактные карточки и перетаскивание точек, без лишних кнопок «вверх/вниз».

## P0 — обязательно закрыть до рабочего теста

### 1. Сохранение рейса и прогресса в Room без потерь
- Довести Room до единственного надёжного источника активного рейса и прогресса.
- Убрать риск рассинхронизации между Room и SharedPreferences: сейчас репозиторий содержит совместимость со старым хранилищем, а прогресс ещё синхронизируется отдельными операциями.
- Проверить восстановление активного рейса после принудительного закрытия и перезапуска приложения.
- Проверить, что редактирование/перестановка точек не сбрасывает сканирование, расхождения, подписи и фото.
- Проверить архивирование и восстановление предыдущего рейса.

### 2. Сканирование одинаковых товаров и уникальных коробок
- Обычный EAN/GTIN — код товара, а не уникальный идентификатор физической коробки. Повторное сканирование одинакового EAN не должно ошибочно считаться дубликатом коробки.
- При совпадении общего товарного кода показывать все подходящие позиции и точки с ожидаемым количеством; не выбирать первый магазин молча.
- Учитывать SSCC (GS1 AI 00) и серийный номер (AI 21) как уникальные идентификаторы только при наличии соответствующих данных.
- Подтвердить корректную обработку GS1-128, Data Matrix, QR, EAN-13 и UPC-A, включая разделители GS1/FNC1.
- Отдельно проверить сценарий генерации QR-кода: в предыдущем функциональном аудите генерация QR не была найдена. Если QR нужен для маркировки/идентификации груза, добавить генерацию с устойчивым ID и тестами; не подменять ею уникальный SSCC и не генерировать фиктивные коды без согласованного формата.
- Добавить тесты: одинаковый товар на нескольких точках, одинаковый товар в нескольких накладных одной точки, повтор уникального SSCC, неизвестный код, лишнее/недостача.

### 3. Жизненный цикл камеры
- Проверить запуск/остановку CameraX при уходе экрана в фон, сворачивании приложения, блокировке экрана и возврате.
- Проверить разрешение камеры, отказ в разрешении, фонарик и повторный вход в сканер.
- Не допускать параллельных CameraX-сессий и зависшего состояния сканера.
- Проверить на реальном телефоне, а не только по факту компиляции.

### 4. Импорт накладных
- Сохранить текущий импорт CSV/TSV и базовый XLSX-парсер, но проверить на реальных обезличенных накладных.
- Для XLSX: выбор листа, несколько листов, заголовки не в первой строке, пустые строки, объединённые ячейки и связанные таблицы — по фактической структуре файла.
- PDF и фото бумажной накладной: добавить извлечение текста/OCR и экран проверки распознанных полей до создания рейса.
- Не угадывать соответствия колонок: неизвестные поля должны настраиваться/подтверждаться пользователем.
- После импорта показать сводку: количество точек, накладных, позиций и мест; ошибки импорта не должны молча теряться.
- Для окончательной настройки схемы нужен обезличенный рабочий файл накладной и несколько образцов этикеток.

## P1 — завершить рабочий сценарий водителя

### 5. Карточка точки и закрытие доставки
- В карточке точки должны быть адрес, телефон, контактное лицо, временное окно, комментарии и состав груза по накладным.
- Статусы точки: ожидает, в работе, завершена, есть расхождение.
- Поддержать причины расхождений: брак, недовоз, излишек; не разрешать закрывать точку с незаполненными/некорректными расхождениями.
- Добавить подпись получателя и фото подтверждающих документов; хранить локально, сохранять связь с точкой и восстанавливать после перезапуска.
- Проверить выдачу разрешений и доступ к сохранённым фото после перезапуска/перезагрузки.

### 6. Маршрут и Яндекс Навигатор
- Довести запуск маршрута из списка точек через Яндекс Навигатор.
- Проверить deep link на устройстве с установленным Яндекс Навигатором и поведение, если приложение не установлено.
- Учитывать ограничение числа промежуточных точек: разбивать длинный маршрут на последовательные сегменты с общей переходной точкой.
- Проверить координаты/адреса, порядок точек и передачу начальной/конечной точки.
- Маршрут по фотографии: фото из галереи → OCR → ручная проверка адресов → геокодирование → применение точек в активный рейс. Не строить маршрут по непроверенным/неразобранным адресам.
- Не обещать дорожную оптимизацию, пробки или офлайн-навигацию без реального подтверждённого сервиса.

### 7. Перестановка и редактирование точек
- Drag-and-drop должен менять порядок в активном рейсе и сохраняться в Room.
- Проверить ручное редактирование названия, адреса, телефона, временного окна и комментария.
- После изменения порядка повторный запуск навигации должен использовать новый порядок.

## P2 — отчётность и удобство

### 8. Отчёты и история
- Проверить CSV-экспорт: UTF-8 BOM, кириллица, кавычки/разделители, корректные суммы ожидаемого/отсканированного/расхождений.
- Отчёт по точкам и накладным должен явно показывать незавершённые позиции и причины расхождений.
- Проверить историю рейсов, архивирование и восстановление.

### 9. Каталог товаров
- Проверить локальный каталог товаров: поиск по штрихкоду/названию, обновление из накладных и отсутствие дублей.
- Каталог не должен подменять фактические данные накладной.

### 10. Финальная проверка интерфейса
- Пройти все экраны в светлой и тёмной теме. Убрать оставшиеся жёстко заданные цвета, которые ломают выбранную палитру.
- Проверить крупные элементы, читаемость в кабине при слабом освещении, системные панели, клавиатуру, прокрутку и состояния загрузки/ошибок/пустых списков.
- Сверить главный экран и список точек с утверждённым industrial / graphite макетом.

## Проверки релиза

- Unit tests проходят.
- GitHub Actions действительно назначает hosted runner, а не падает до старта job.
- После каждого набора изменений проверять актуальный workflow на текущем SHA в `main`.
- APK выдавать только из успешного workflow текущего коммита; старые APK не считать актуальными.
- На двух Android-телефонах проверить импорт, перезапуск/восстановление, сканирование, закрытие точки, подпись/фото и переход в Яндекс Навигатор.
- Не отмечать функцию готовой только по наличию файла или успешной компиляции.
