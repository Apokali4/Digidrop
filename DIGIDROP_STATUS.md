# DigiDrop: состояние проекта

## Основа
- Отдельный Android-проект DigiDrop на базе предоставленного QRHelper source archive.
- Видимое имя приложения: DigiDrop.
- Основная архитектура пока остаётся локальной: backend/Firebase не добавлялись.
- Камера: CameraX + ML Kit Barcode Scanning.

## Важно по рабочим этикеткам
- На фото коробок читается длинный линейный GS1-подобный идентификатор с AI `01`, `11`, `21`.
- В проекте ML Kit сканирует все поддерживаемые форматы; точная обработка GS1 AI и проверка по фактическому сканированию ещё не подтверждены.
- На бумажном документе есть линейный штрихкод с подписью `RU0141582293` и отдельный 2D-код. Формат 2D-кода по фото достоверно не определён.

## Текущее состояние функций
- [x] Камерный сканер CameraX + ML Kit присутствует в исходнике.
- [x] Импорт текстовых CSV/TSV накладных с разделителями, кавычками и координатами присутствует в рабочей копии.
- [x] Тестовая кнопка, подставлявшая фиктивный штрихкод, удалена из рабочей копии.
- [x] Фейковый демо-маршрут удалён из стартового состояния рабочей копии.
- [ ] XLSX не реализован.
- [ ] PDF/скан-фото накладных как импортируемый маршрут не реализован.
- [ ] Группировка нескольких документов и товарных строк в сущности рейс → точка → документы → товары → упаковки требует доработки.
- [ ] Сверка фактических упаковок, пропусков, дублей и неизвестных кодов не подтверждена.
- [ ] Геокодирование адресов и построение реального дорожного маршрута не реализованы.
- [ ] Проверка на настоящих этикетках и на устройстве не проведена.
- [x] Последний импортированный CSV/TSV сохраняется локально и восстанавливается после перезапуска.
- [x] Системная кнопка «Назад» обрабатывает переходы между хабом, точками, деталями и сканером; сканер возвращает на экран, с которого был открыт.
- [x] Для навигации добавлен запасной переход в Яндекс Карты через браузер, если обработчик `geo:` не найден.
- [x] Обычные EAN/UPC длиной 8, 12–14 цифр больше не засчитываются как уникальная физическая коробка; они используются как поиск товара. Совпадения в нескольких накладных показываются как неоднозначные.

## CI
GitHub Actions workflow `.github/workflows/android.yml` собирает `assembleDebug` на Ubuntu и сохраняет APK в Actions artifact. Используется Android SDK Platform 36 и Build Tools 36.0.0. Сборка изменений коммита `907a19e` выполняется; итог ещё не подтверждён.

## Известные ограничения
- Правило «EAN 8/12–14 цифр не является уникальной коробкой» — безопасная эвристика, но не полноценный разбор GS1. Уникальность AI `21` и SSCC AI `00` ещё не извлекается и не проверяется.
- Для уникальных длинных кодов остаётся точное сравнение с полем штрихкода из импортированной строки. Реальное соответствие формату накладной пока неизвестно.
- Если пользовательский файл содержит не CSV/TSV, его пока нельзя импортировать. Не выбирать Excel/PDF как поддерживаемые форматы до реализации и проверки.

## Честный статус
Не объявлять приложение готовым для реального рабочего рейса, пока не проверены импорт реального файла накладной, сканирование всех видов кодов с упаковок и сверка количества мест на Android-устройстве.
