# DigiDrop — текущее состояние

Дата обновления: 2026-11-06

## Реализовано в исходном коде

- Светлая приглушённая рабочая тема, рассчитанная на слабое освещение.
- Главный экран, список точек, экран точки со всеми строками/накладными, экран отдельной строки.
- Группировка строк по магазину и адресу; несколько накладных одной точки отображаются вместе.
- CameraX + Google ML Kit для распознавания поддерживаемых линейных и 2D-кодов.
- Включение фонарика, запрос разрешения камеры.
- Поиск точного кода по загруженному рейсу.
- При совпадении кода с несколькими строками показываются все подходящие точки и суммы количеств по каждой точке.
- Обычный розничный EAN не считается уникальной физической коробкой и не увеличивает счётчик сканирований.
- Базовая обработка GS1: извлечение GTIN AI (01), распознавание наличия AI (00) SSCC / AI (21) serial как признаков уникального идентификатора.
- Импорт CSV/TSV и базовый XLSX-парсер первого листа (shared strings, inline strings, ячейки по координатам).
- Локальное сохранение импортированного рейса в SharedPreferences и восстановление при следующем запуске.
- Раздельные ключи прогресса для разных строк с одинаковым товарным штрихкодом.
- Экспорт CSV с UTF-8 BOM и экранированием полей.
- Открытие внешнего картографического приложения через geo: и резервный URL Яндекс Карт.
- Звонок через системный экран набора номера.
- Сброс локального прогресса и списка неизвестных кодов.

## Ограничения, которые остаются

- XLSX: читается первый лист; выбор листа/машины и сложные книги с несколькими связанными таблицами пока не реализованы.
- PDF и фотографии бумажных накладных не импортируются; OCR не реализован.
- Парсер CSV/TSV/XLSX рассчитан на табличную структуру со столбцами штрихкод, магазин/адрес, товар и количество. Реальная схема логистической выгрузки пока неизвестна.
- GS1 обработан ограниченно. Полная спецификация GS1, все разделители FNC1 и любые варианты AI не реализованы.
- Если на нескольких точках один и тот же GTIN товара и на коробках нет уникального SSCC/серийного кода, определить физическую коробку для конкретного магазина математически невозможно. Приложение показывает варианты, а не угадывает.
- Подсчёт отсканированных упаковок возможен только для кодов, которые действительно уникальны и присутствуют в данных рейса. Сканирование обычного товарного EAN служит поиском товара/назначений, а не учётом каждой коробки.
- Геокодирование адресов зависит от доступности сетевого сервиса. Офлайн-открытие карт возможно только если на устройстве установлено приложение, способное обработать geo: URI.
- Автоматическая дорожная оптимизация с пробками не реализована; координатная сортировка по прямой не является навигационным маршрутом.
- Нет проверки на реальных этикетках и конкретном Android-телефоне в текущем окружении.

## CI / проверка

- Сборка запускается через GitHub Actions: `assembleDebug`, SDK 36, JDK 17.
- Последний исходный коммит на момент этого отчёта: 94135cb536454aa1f59cff60a39f0b4374a0a671.
- Последняя сборка этого коммита должна быть проверена до выдачи APK. Не считать успешными более ранние workflow-запуски, собранные с промежуточными коммитами.
- Успешная компиляция не подтверждает работу камеры, навигации и импорта на пользовательском устройстве.

## Подготовка к рабочему тесту

Для реального теста нужен исходный файл накладных (можно обезличить названия, телефоны и адреса, сохранив структуру и заголовки) и хотя бы несколько этикеток/штрихкодов. Без них нельзя честно подтвердить соответствие столбцов и однозначность привязки коробки к точке.
